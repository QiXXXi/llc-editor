# 边狱公司 · 自定义人格 / E.G.O 编辑器

参考[灰机 · 边狱公司中文维基](https://limbuscompany.huijiwiki.com/)的页面结构做的离线编辑器：自己造人格和 E.G.O，右边实时出仿 wiki 的详情卡，能导出 PNG 卡片、JSON 存档和 wiki 文本。

**双击 `index.html` 就能用。** 不需要服务器、不需要联网、不需要装任何东西 —— 整个应用（含 190 个人格、116 个 E.G.O、306 张立绘、1587 个游戏图标）就是一个 9.58 MB 的 HTML 文件。

---

## 用法

| 想干的事 | 怎么做 |
|---|---|
| 从现成的改 | 左栏「内置库」→ 点任意条目 = 就地打开来改（改动只在内存里，刷新即回退） |
| 留下来 | 内置库里点右边的 **＋** = 复制一份到「我的」，从此随便改、会存盘 |
| 从零开始 | 顶栏「＋ 新建人格」/「＋ 新建 E.G.O」 |
| 换立绘 | 预览栏「上传立绘」，选本地图片（自动缩到长边 ≤512 的 webp 存起来） |
| 出图 | 「导出 PNG」，2 倍分辨率，带立绘 |
| 存档 / 分享 | 「导出 JSON」，别人用「导入 JSON」读回来（可选追加 / 合并 / 替换） |
| 发到 wiki | 顶栏或预览栏的「导出文本」（右侧下拉选格式：灰机 wikitext / 通用 MediaWiki 表格）。导出后正文会摊在预览栏底部的抽屉里，方便直接复制 |

快捷键：`Ctrl+Z` 撤销、`Ctrl+S` 立即保存、`Ctrl+P` 导出 PNG、`Ctrl+E` 导出文本；效果行里 `Ctrl+Enter` 加下一行。

改动自动存在本机浏览器的 localStorage 里（防抖写入，关页面前也会补写一次）。**「我的」条目多了记得导出 JSON 备份** —— 换浏览器、清缓存、用无痕窗口都会丢。

### 效果文本里的两个小语法

- `**沉沦**` → 状态名加粗。导出 wikitext 时会自动还原成 `{{状态2|沉沦}}`。
- 每条效果行是「硬币序号 + 触发时机 + 文本」。卡片上硬币序号画成灰机的 `硬币N.png`，触发时机画成 `[命中时]` 这样带方括号的彩字（颜色查灰机的 `模板:颜色`），没有硬币号的就是技能级效果、不画硬币图标。

### 特性关键词里的除名词条：`~~被除名的词条~~`

灰机的特性关键词（`Data:Identitychoose.tabx` 的 `tag` 列）里有几个词条是**划掉的**，意思是「已被除名」：

```html
H公司，<span style="color:#d40000"><s>贾&zwnj;家</s></span>
```

这是内联 HTML，直接喂进 canvas 只会把 `<span` 一个字母一个字母画出来 —— 解析器里原本就是这么错的。`tools/parse_seed.py` 的 `html_to_text()` 现在负责转换：

- `<s>…</s>` / `<del>` / `<strike>` → `~~…~~`（**必须在拆词之前**转：`~~大师~~` 是一整个词，拆完再补记号就补不回去了）
- 其余标签一律抹掉只留文字（`<span class="heimu">天杀星</span>` 这种黑幕，取的就是里面的字）
- `&zwnj;` 之类的零宽字符删掉，`html.unescape()` 收尾

卡片这边只认 `~~` 这个记号、不认识 HTML，所以**手写 `~~大师~~` 和内置数据走的是同一条路**。`splitStrike()` 把成对的 `~~` 抠出来，`Surface.chip(..., {strike:true})` 在文字正中间压一道 1.4px 的横线（横线只跨文字、不含标签内边距）。没闭合的 `~~` 当普通文字，不会把打了一半的输入吃掉。

**除名词条整块用灰机那个红 `#d40000`**（字和横线都是），色号就是从上面那段内联样式里抄的，不是自己挑的。灰机在白底正文和 `#222` 的表格里用的都是同一个值，所以深浅两套主题共用它、不做调整 —— `THEMES.*.del` 里就这一个色号。

`smoke_test.py` 的「3e」拿真实的鸿璐蜘蛛巢环指父辈来比：同一张卡去掉 `~~` 再渲染，差异应该正好是那一个标签（≤ 60×30 的方块，实测 23×10），标记版上这个标签的像素**整块都是红的**（107 个红像素，且「变红」的计数等于红像素总数 —— 说明别处没有任何东西跟着变红），其中存在与 `#d40000` 位级相同的像素、还有一行连续 22px 的红横条（就是删除线）；标签外只允许剩零星抗锯齿误差。深浅两套主题各查一遍。再把 4 条带 `~~` 的条目（含「开头就是除名词」和「一条里两个」的拇指父辈）在深浅两套主题下各跑一遍变红检查，顺带扫一遍全部 306 条数据的 `tag`，确认没有残留的 `<` `>` 或 HTML 实体。

### 卡片顶上那条罪人色横条，和「量宽度别拿画图函数凑」

卡片最上面那条 3px 横条是**罪人色**（`Enums.color('sinners', …)`），`draw()` 里一句 `fillRect(0, 0, W, 3, …)`。新建立的人格没填罪人时默认按李箱（`#d4e1e8`）画。

它有一阵子是被一层黑字糊住的：`drawBanner()` 为了算技能名横幅的中段宽度，写的是

```js
var textW = s.tracked(name, 0, 0, SK.bannerTrack, SK.bannerSize, 'bold');
```

`s.tracked()` 的职责是**逐字加字距地画、顺便返回宽度**，于是每画一条技能横幅（EGO 还有觉醒/侵蚀两条）就往画布 (0,0) 落一遍黑色横幅名 —— 卡片顶上就成了「彩色横条 + 一排半截黑字」，技能越多糊得越厚。量宽度得用只量不画的 `Surface.trackedW(str, tracking, size, weight)`（`tracked()` 的数学跟它一模一样，所以横幅宽度、卡片总高都没变）。

改完还剩一个问题：`Surface.text()` 在 `dry`（量高度那一趟）里返回 0 而不是宽度。这目前是无害的 —— 断行是 `flowAtoms()` 用 `atomW()` 单独算的，`drawAtoms()` 返回值只用来推进游标 x，不参与高度。**但新写的代码别指望 `s.text()` 的返回值在 dry 那趟是对的**，要量宽度就用 `measure()` / `trackedW()`。

`smoke_test.py` 的「3f」按导出那条路（scale 2）逐行查这条横条：顶上 6 个设备像素行必须**整行只有罪人色一种颜色**，第 7 行必须**整行只有主题底色一种颜色** —— 多糊一层字（整行混色）或者条子长/短一个像素，都会被逮到。查 2 个人格（含技能最多的）+ 1 个 EGO + 1 个新建，深浅两个主题共 8 遍。

### 内置库：点行 = 就地打开，＋ = 复制一份

**点内置条目不再自动往「我的」里塞副本了**（除非点的是右边那个 ＋）。点行 = 把内置条目打开来改：

- 改动直接改内存里 `SEED.items` 那个对象，**一个字都不写 localStorage**。刷新页面时 `SEED` 从 `<script id="seed">` 重新解析，自然回退到原样。
- 也能改、也能「导出 PNG / 导出文本 / 导出 JSON」—— 导出 JSON 时会单独导出**当前这一条**（它不在 Store 里，走不到「导出全部自定义条目」那条路），信封跟批量导出完全一样，导回来能直接用。
- 立绘存不了：assets 是按 id 记账的，内置条目写进去会留成一条孤儿资源，而且下次打开时会先命中它、看起来像「没回退」。所以点「上传立绘」会提示先复制一份。
- 表单、撤销、卡片全都能用。撤销时是**就地覆盖**字段而不是换对象 —— `SEED.items` 和表单握着同一个引用，换个新对象等于跟列表脱钩。

实现上要盯住的是**别让改动流进 Store**：`openItem` 里那个 `currentIsSeed` 开关同时挡着三条路 —— 输入的 `Store.replace`、撤销的 `Store.replace`、立绘的 `Store.setAsset`。`Store.replace` 找不到 id 时会退化成 `add()`，正是这一条会把「随手点开一个内置人格」变成往「我的」里塞一条。

另外内置库有 306 行、每行一个立绘 `<img>`，编辑时每敲一个字就 `innerHTML` 重建整个列表会卡，所以走的是 `Library.touchActive()`：只改当前高亮那一行的名字和组织，不重建。

### 技能怎么分组：照抄灰机的四个页签，不自己发明「四技能」

技能是**一条可增删的列表**，每一项的「槽位」= 它在灰机 `{{技能链接}}` 里的参数前缀。灰机把这条列表渲染成 **1技能 / 2技能 / 3技能 / 守备技能** 四个页签，同一个页签里放「本体 + 它的强化形态」；卡片照这个来。

分档不是按数字大小排的，而是**照抄 `模板:技能链接` 的 `personalitystage4` 分支里各 div 的出现次序**：

| 页签 | 槽位（按出现次序） |
|---|---|
| 1技能 | `1技能` → `强化1技能` → `强化1技能2` |
| 2技能 | `2技能` → `强化2技能` → `强化2技能2` |
| 3技能 | `3技能` → `5技能` → `强化3技能2` → `强化3技能3` |
| 守备技能 | `4技能` → `7技能` → `6技能` → `强化4技能攻击` |

注意守备那一档是 **`7技能` 排在 `6技能` 前面**、强化形态排最后 —— 按数字排序会排错。这张表在 `src/const.js` 的 `SLOT_ORDER` 里，`Enums.slotRank()` 查它。

举例（构建产物里实测）：赤红之神的 13 条技能 → `1技能{驱力, 我来帮忙, 自我排泄}` `2技能{食欲, 自我卑贱化, 要求}` `3技能{赤红洗礼, 存在的缺失, 贪求, 阉割}` `守备技能{逃离, 护卫, 一元特征}`。

同一个页签里的多个变体之间画一条 2px 白线 —— 那是灰机自己在技能块之间插的 `<div style="border-top: 2px solid white">`。

没有 `-类型` 参数的槽位一律按守备技能处理（希斯克利夫的 `7技能 掩护` 就是一条没有类型的可拼点防御）。

### 卡片按灰机原样画

卡片是**照着灰机页面的像素做的**，不是「看着差不多」的自由发挥。能用图标的地方一律用游戏素材，不写文字：

| 位置 | 画法 |
|---|---|
| 生命 / 防御 / 速度Ⅰ~Ⅳ / 混乱阈值 | `数值图标-生命`（30px，和灰机同宽）、`数值图标-防御`、`数值图标-速度-1..4`（游戏里就是Ⅰ/Ⅱ/Ⅲ/Ⅳ四个字），数值跟在图标右边。**速度Ⅳ 数据表里是空的**（`Identitychoose.tabx` 的 `u4_spd` 190 行空 189 行），卡片跟灰机页面一样把速度Ⅲ 顺延下来（灰机自己的页面就是同一个 `<span id="sinnerlevel10">` 印两遍），不印 `–` |
| 攻击类型（斩击 / 突刺 / 打击） | 灰机的 `斩击.png` / `突刺.png` / `打击.png`，宽度按灰机的 40 / 50 / 40 px |
| 技能块 | `数值图标-攻击` 35px + 修正值，起点和灰机实测的 x=115 一致；守备技能换成 `数值图标-守备` |
| 攻击容量 | 「攻击容量」+ **一横排 `数值图标-攻击容量` 黄方块**（20px，间隔 3px），不写数字。人格技能的标签色是 `#F0BC00`、E.G.O 那条是 `#ffe71b`（灰机两个页面上用的就不是同一个黄） |
| E.G.O 技能的数值行 | 每个解析阶段都画一行「基础值 / 硬币威力 / 攻击容量」（灰机 `升阶属性` 表里那三行 `基础值：14<br>硬币威力：+6<br>攻击容量：1`，卡片压成一行）。攻击容量同样走黄方块 |
| 硬币数 | **一横排 `硬币.png`**（20px，间隔 2px），第一枚的位置就是原来那个硬币的位置（x=130），不写「硬币×N」；E.G.O 技能头那一串是 14px 从右往左排 |
| 硬币序号 | 正文里每条效果的 `硬币1/2/3` 行首图标 |
| 罪孽 | 七罪孽 `罪孽-X.png` + 抗性箭头，技能卡左上角是 `{罪孽}-等级N.png` 六边形框 + `-底部` 装饰 |
| 技能贴图与框的叠放 | 先画 `-底部`（实心六边形底板）→ 再画技能贴图（裁成六边形）→ 最后画 `{罪孽}-等级N`（中间透明的描边环）。**顺序不能反**：灰机的 HTML 里框是 `z-index:2`、贴图是 `z-index:auto`，框压在贴图上 |
| 技能徽章 | `{罪孽}-{类型}-暗色.png`（30×28），人格挂在六边形下面、E.G.O 挂在立绘下面 |
| 技能名横幅 | 底图 `BattleUI_CoinPopup_skillName.png`（9 切片：左端盖 9px + 中段拉伸 + 右端盖 55px，整体摊到 183.385×32），**底色按技能自己的罪孽染** —— 见下面「技能名横幅的颜色」 |
| 状态效果 | 正文里的 `**状态**` 渲染成「图标 15px + 分类色文字 + 黑2.5px 托彩1.5px 双层下划线」，图标查 `Data:Buff.tabx` 的名字 |
| 被除名的特性关键词 | 灰机上划掉的词条（`<s>`）在卡片上是压着字的一道红横线（`#d40000`），见下面「除名词条」 |
| E.G.O 被动的阶段标签 | 灰机 `模板:EGO被动链接` 那一格是**写死的「异想解析阶段Ⅱ」**（被动在解析Ⅱ 解锁，116 个页面全是这一档），卡片跟它走；被动名的颜色也是灰机那个橙 `#DC9012` |

**特殊标签的颜色一个都没改**，全部查灰机自己的表：

- 触发时机（`[命中时]` `[使用时]` `[正面命中时]` …）查 `模板:颜色` 的 `WIKI_COLOR` 表
- 状态效果的分类色：正面 `#daa520`、负面 `#FF0000`、状态 `#76BF32`、特殊 `#815530`；专属于某罪孽的状态（`{{罪孽颜色|…}}`）用该罪孽的颜色而不是分类色
- 抗性档位色（查 `模板:颜色` 的 `×N` 条目）：`×0.5` `#828282`、`×0.75` `#b6b8b7`、`×1` `#e2c090`、`×1.5` `#ff918a`、`×2` `#ff0000`
- 抗性格子里印的是**倍率本身** `[×2]` `[×0.5]` `[×1]`，不是档位名「致命 / 耐性 / 一般」—— 灰机页面上就是这样（档位名只出现在筛选下拉框里）
- 技能名横幅的底色：灰机那张底图本身是**白的**，颜色由 `MediaWiki:Common.js` 在浏览器里刷上去，色号表就是它里面的 `COLOR_MAP`（`暴怒 #A0392B` … `常规 #a16a3b`）—— 和 `模板:颜色` 的罪孽色号**逐个相同**

### 技能名横幅的颜色：构建时染，不是运行时染

灰机做这件事的代码在 `MediaWiki:Common.js` 的 `applyColor()` 里 —— 把底图逐像素乘成目标色：

```js
var brightness = (data[i] + data[i+1] + data[i+2]) / 765;   // 0~1 的亮度当权重
data[i] = r * brightness; data[i+1] = g * brightness; data[i+2] = b * brightness;
```

白的地方变成纯罪孽色，描边那些深灰变成同色系的暗调，alpha 不动。

我们**不学它在页面里现算**（卡片是 canvas，本来就要 data URL，运行时去 `getImageData` 一圈既慢又容易把 `toBlob` 搞脏），而是在 `parse_seed.py` 里用等价的 Python 把底图染成 8 张（7 罪孽 + 常规）内嵌，运行时 `drawBanner()` 只是按技能自己的罪孽挑一张。

色号不另抄一份：`parse_seed.py` 直接从 `src/const.js` 的 `SINS` 表和 `src/card.js` 的 `NEUTRAL_SIN_COLOR` 里读（读不到就报错停下），和罪孽菱形、技能框用的是同一份。

`smoke_test.py` 的「3c」把 `Common.js` 那段循环**原样**在 Edge 里跑一遍，跟内嵌的那张逐像素比：不透明像素**逐位相同**，只差在半透明边像素的预乘取整上（眼睛看不出来的量级）。改色号、改算法、改底图尺寸，这条都会当场炸。

技能块的尺寸也是量出来的而不是估的：`灰机容器内宽 893`（+ 左右各 14px 内边距 = 卡片默认宽 **921**），正文 16px、**行高 28.8**（`#content p{line-height:1.8}` = 16×1.8）、带 30px 硬币图标那行 **30.7**（硬币撑破行盒，把**下一行**多顶下去 1.9px；那一行自己的字不动）。这些常量在 `src/card.js` 顶部的 `SK` 表里，出处是 `_ref/huiji/probe/measure.json`（对活页面逐个 `getBoundingClientRect()` 量的）。

⚠️ 量尺寸**必须带真站 CSS**（`tools/wiki_page.py`）：缓存页的 `<link href="/load.php?…">` 是相对路径、`file://` 下必然 404，整站皮肤样式全丢之后 `<p>` 退回 UA 的 `margin:1em 0`、行高退回 `normal` —— 于是量出来是 60×**64** 的裁剪框、偏下 **8.5px** 的底色板、行高 28 / 32。早期版本的常量就是这么量错的。

### 技能图标（六边形）那块的三张图

描边框、六边形贴图、底色板的摆位**逐罪孽 × 逐等级都不一样**，是 `模板:{罪孽}技能图标` 里一组组写死的 margin，不是统一值 —— 所以卡片也逐档存：`src/const.js` 的 `SIN_GEOM`（八行 × 三档 × 六个数），原文留档在 `_ref/huiji/probe/tpl_*技能图标.txt`，`tools/probe_icon_geom.py` 会把模板重抓一遍并把结果写进 `_ref/huiji/probe/skill_icon_geom.json`。

两个容易踩的点：

- **六边形的裁剪框是正方形。** `clip-path` 挂在那个 div 上，div 里只有一个行内 `<img>`，所以 div 的高度就是**行盒**高度：真站 `#content p{line-height:1.8}` 下正好等于图高，20 个裁剪框实测一律 **60×60**。曾经照缓存页（行高退回 `normal`，行盒多出 4px 降部）量成 60×64、并据此把六边形纵向拉开过，那是错的。`_ref/probe_icon/side_by_side.png`（`tools/cmp_icon.py` 生成）是两边按图标外接矩形对齐的对照图，高宽比逐位对得上。
- **底色板的 y 要把 `<p>` 的上外边距算进去。** 那张图在模板里**独占一行**，MediaWiki 会给它套一个 `<p>`（`margin:7.5px 0`），又往下顶 7.5px —— 只有暴食和嫉妒两张模板少写了一个换行，不吃这 7.5px。`SIN_GEOM` 里的底板 y = 模板 margin + 7.5（暴食/嫉妒不加），`tools/probe_icon_geom.py` 会把八个模板重抓一遍、再对活页面逐项对账。

`smoke_test.py` 的「4d」把 canvas 的 `drawImage` / `moveTo` / `lineTo` 调用录下来，直接看卡片**实际画到哪**（六档：傲慢 1技能、嫉妒 2技能、怠惰 3技能、忧郁 1技能、常规 1/3技能），再跟活页面上量到的数比 —— 连六边形的宽度、高宽比、底顶点位置一起查。

### 唯一一处故意不照抄灰机：守备技能的技能框

灰机的 `模板:技能text` 给普通防御 / 闪避印的是**中性的「无属性」框**（`常规-等级1`），因为模板参数默认就是空。但守备技能在同步Ⅳ **本来就有罪孽属性**（奥提斯的「防御」是怠惰），而卡片只画同步Ⅳ —— 所以卡片直接画这个技能自己的罪孽框，不退回中性。

这是用户点名要的（「wiki 上图标显示是无属性，但我们把属性加上」），也是整个卡片上**唯一**一处明知灰机长什么样却故意改掉的地方。除技能框外，普通防御 / 闪避仍然照灰机的模板走：数值行用「守备」图标、**不画**罪孽×攻击类型徽章。

### 卡片只画同步阶段Ⅳ

内置数据里每一阶都有数值和效果，但四阶全铺在卡片上就是一眼望过去全是字。所以卡片默认**只画满级那一阶**（人格同步Ⅳ / E.G.O 解析Ⅳ），预览栏的下拉切到「全部阶段」才四个都画。**四阶数据一直留着**：灰机的 `{{技能链接}}` 模板需要 1/2/3/4 阶的参数，导 wikitext 时一阶都不能少。

### 几个容易踩的坑（都写进代码注释了）

- **拼接顺序写死在 `build.py` 的 `ORDER` 里**，不靠 glob 字母序：`const.js` 必须最先（其它文件在模块加载期就读枚举），`app.js` 最后（它在加载期末尾自动 boot）。
- **种子 JSON 里每个 `<` 都转成 `\u003c`**：数据里只要出现一个字面量 `</script>`，浏览器会当场截断 script 块，页面白屏。
- **`file://` 下 Origin 是 `null`**：不能用 ES `import`、`fetch`、Web Worker，`crypto.randomUUID` 不可靠，localStorage 规范上未定义 —— 所以启动时探一次可用性，探不通就退到内存模式并在顶栏提示。
- **`toNum("")` 返回 `null` 而不是 `0`**：不然空输入框会被 `Number("") === 0` 变成 0 分。
- **编号和稀有度存字符串**：`"0102"` / `"000"` 存数字会丢前导零。
- **阶段是否开启要判 `toNum` 之后的值**：存档里没有的阶是 `power: null` 而不是 `undefined`，写 `!== undefined` 会让每一阶都被点亮，导出再导入就会凭空长出没有数据的阶。
- **`form.js` 里的 `GROUPS` 是张白名单**：`schema.js` 加一个 `e: 'xxx'` 的枚举组，还得在 `GROUPS` 里登记一次，否则那个下拉框只有一个空选项（「技能种类」就这么哑过一次 —— 选中项设成 `def` 会静默跳回空串，技能块也就不重建了）。
- **`_opts` 的 `blank=false` 表示「不给空选项」**：不特判就会印出一个写着 `false` 的选项。
- **技能槽位名同时是显示标签和 wikitext 参数前缀**：`强化1技能` 改一个字，导出的 `|强化1技能-名称=` 就跟着变 —— 这是有意的，改它等于改导出结构。
- **图标「有没有」必须在测量那一趟就定下来**：`hasIcon(name)` 只查资源表里有没有这个键，不看图解码没解码完。否则量高度那趟还没解码（不画），画那趟解码好了（画），两趟算出来的高度不一样，卡片就会错位。
- **E.G.O 技能块的标题要先让出右边那一串数值**：`硬币×N / 理智消耗 / 修正值` 是右对齐的，得先排它、再拿它的左边界当标题的可用宽度（摆不下先降字号再截断）。反过来写的话「致智慧与苦难」这种长名字会直接压到数值上。
- **`setAssets` 要同步调用，等图解码是另一回事**：`loadIcons()` 里先把 `Image` 对象登记进表、再挂 `onload`，解码完再排一次重绘补图。`Card.setAssets` 必须在开画之前同步交出去。
- **预览画布只写 `style.width`，不许写 `style.height`**：卡片默认 921px 而预览栏比它窄，`max-width:100%` 一定会把宽度压下来。这时高度必须交给 CSS 的 `#card { height:auto }` 按 canvas 的固有宽高比缩 —— 内联 `style.height` 压得过样式表里的 `height:auto`，一写上去画布就**左右挤扁**（宽度缩了、高度没缩）。`smoke_test.py` 的「3b」专门压到 460px 比对宽高比盯着这条。
- **技能名横幅的颜色在 `MediaWiki:Common.js` 里，不在模板里**：`Html:Textcolorskill` 那个 Html 页只有一个**空的** `<script></script>` 和一张白底图，`data-color` 属性摆在那儿看着像已经染好了 —— 照着那个页面的 HTML 抄，横幅就永远是白的。真正染色的是站点的 `MediaWiki:Common.js`（`COLOR_MAP` + `applyColor()`），翻页面的 HTML 翻不到，得去翻站点 JS。
